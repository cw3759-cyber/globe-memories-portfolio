# AI 的作用与产品边界

## 已发生的 AI 使用

作者确认使用 AI coding 实现，由本人承担全程产品设计。具体工具名称、模型名称、提示词历史和逐次生成记录未提供，不补写为事实。

产品运行时没有大模型调用、向量数据库、RAG、训练管线或自动生成回忆功能。地理聚合是距离规则，图片处理是常规图像压缩；均不应包装成 AI 推理。

面向 AI 产品经理岗位，可以讨论需求分解、AI 辅助实现后的验收、规则与模型的适用边界。本项目本身不能证明线上模型评测或 AI 产品商业效果。

## 可探索的能力：从文字预填回忆信息（未实现）

问题假设：用户已经写出一段经历，重复填写日期、地点和标题增加记录负担。应先观察表单任务的实际卡点，再决定是否值得加入 AI。

建议流程：用户主动提交文字 → 模型提取候选字段 → 结构化校验 → 地名服务提供坐标候选 → 用户确认 → 保存。任何不明确的日期、位置保留为空或候选，不能自动补成真实经历。

- 模型：未选型。先用相同样例对比可用模型的提取质量、延迟与成本，不预设某款模型更优。
- 数据：只用自建虚构文本或获得同意的样例；不使用作者私人照片和对话做训练。
- 基线：手动填写，以及日期规则识别加地名查询。
- 评测：字段准确率、无依据补全率、用户修改比例、端到端完成时间；另统计超时与单次成本。
- 失败路径：超时、无候选或输出不合规时退回手动填写；不自动重写用户原文。
- 上线门槛：应在预先约定样例上显示真实任务收益，并由用户确认写入。指标门槛待基线测量后设定。

这是一份候选产品方案，不是已实施路线图或历史成果。
